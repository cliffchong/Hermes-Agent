## 已實作功能
- **新增**：輸入框 + Enter 或 Add 按鈕；trim、空值忽略、上限 300 字。
- **完成／取消完成**：原生 checkbox（`appearance:none` 自繪）＝保留原生語意與鍵盤操作；記錄 `completedAt`，列表顯示完成日期。
- **刪除**：每行刪除鍵；附 6 秒 Undo toast 與 `Ctrl/Cmd+Z` 復原（刪除與 Clear completed 皆可復原）。
- **重新命名**：雙擊文字或按鉛筆鍵；Enter 儲存、Esc 取消、失焦儲存。
- **篩選**：All / Active / Done（帶即時數量）＋ Clear completed（無已完成時自動 disabled）。
- **狀態顯示**：標題下方「N tasks left · M done」＋ 3px 進度線。
- **持久化**：`localStorage['helen.todo.v1']`，存 `{v, tasks, filter, theme}`；讀取時逐筆驗證（`normalizeTask`），壞資料自動丟棄不致命；`try/catch` 包住寫入，失敗會用 aria-live 通知。
- **主題**：auto／light／dark 三態循環，跟隨 `prefers-color-scheme`，設定一併持久化。
- **鍵盤**：`/` 聚焦輸入、`Enter` 新增、`Esc` 取消編輯或關閉 toast、`Ctrl/Cmd+Z` 復原。
- **無障礙**：`aria-pressed` 篩選狀態、每行 checkbox/按鈕有 `aria-label`、`aria-live` 播報、`:focus-visible` 焦點環、44px 觸控目標、`prefers-reduced-motion` 降階。
- **安全**：一律用 `textContent` 建 DOM，使用者輸入永不當 HTML 解析（已測 `<img onerror>` 注入，`window.__pwned` 未被觸發）。
- **`?demo=1`**：載入示範資料且不寫入 localStorage（方便截圖／展示）。

## 設計取向
- Surface 定位為 **Operate**（使用者對清單採取動作）：不做 hero、不做三卡佈局；輸入列是唯一視覺重心，清單密度優先。
- 色系：暖紙色中性色 + 單一 teal 強調色（不用預設 indigo），襯線標題 + 精確無襯線 UI + mono 快捷鍵。

## 遇到的坑（重要）
1. `actions/configure-pages` 的 `enablement: true` **必定失敗**：`Create Pages site failed. Error: Resource not accessible by integration`。原因：建立 Pages 網站係 repo 管理員操作，自動 `GITHUB_TOKEN` 永遠做唔到（查證：actions/configure-pages#40 等）。→ 已移除該 flag，改為一次性人手開啟 Pages。
2. 老闆手上嘅 fine-grained PAT 有 repo admin 但**無 Pages 權限**：`GET/POST/PUT /repos/.../pages` 全部 403 `Resource not accessible by personal access token`。（現時已經唔需要 Pages 權限，因為網站已由老闆在 Settings 開啟。）
3. 老闆在 Settings → Pages 先選了 default（deploy from a branch, legacy），當時網站即時生效；之後改為 source = **GitHub Actions**（`build_type: workflow`）。
4. 發佈有傳播延遲：deploy job 成功後約 2 分鐘，CDN 才會轉為新 artifact（`COMMIT.txt` 首次 404，其後 200）。查詢時要用隨機 query string 繞過 Fastly 快取。
